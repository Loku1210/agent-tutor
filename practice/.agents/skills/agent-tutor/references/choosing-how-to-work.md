# Choosing how to work

Explain the simplest choice in terms of the learner's task.

| Choice | When it helps | Plain-language example |
|---|---|---|
| One agent | One clear result, shared context, or changes that touch the same files. | “我先整理这份笔记，再打开结果核对一遍。” |
| Separate agents in parallel | Independent tasks can happen at the same time, with distinct outputs and a clear person or agent to combine and check them. Use only when the time or independence gained justifies the extra reviews and resource use. | “两份材料可以同时读，各自写一页摘要，最后由我检查重叠和遗漏。” |
| Steps with dependencies, sometimes called a graph | Some steps must wait for earlier results, there are explicit branches, or an independent check determines whether the work moves forward. A short sequence can use one agent, and a graph may also contain automated checks or user decisions. | “先冻结数据表，再分别做图和检查数值，两个结果都齐了才更新报告。” |

A checklist and one agent are enough for a straightforward sequence. For parallel work, define each piece, its inputs and outputs, who combines the work, and how the combined result will be checked. Keep each writable file with one owner. For a workflow with dependencies, identify what each step waits for, what lets it proceed, and when a failed step stops or goes back for a focused retry.

Before actually starting extra agents, check that the current platform supports them. Explain who would do what and any meaningful time, cost, or review tradeoff. A user's clear request for that specific split can supply confirmation when the platform permits it. If the proposed split, access, or cost is still unclear, ask first. When coordination tools are unavailable, explain the limitation and offer a sequence one agent can do. Never report that an agent, test, or stage ran without observed evidence.
